\subsection{repositories and how to use them}

Creating a new repository is as simple as clicking "New repository," opening it on the computer, and "Push"-ing it onto the github network. 

Whenever you are adding something new to a github repository, it is wise to open a "Branch." Branches are designed to copy the current version of the code without breaking the current working version, typically referred to as "main" or "master." Branches can be made by clicking on the branch icon and creating a new Branch.

When you want to collaborate on a piece of code, or specifically, want to change something, one can submit a "Pull Request" in which collaborators can offer advise to changes on code before they are pulled.

To merge branches, one can submit a merge request. Once the merge request has been passed, one can delete a branch once it is transferred onto the main branch.

\subsection{Makefiles}

Suppose that the file structure of a given project consists of a main file, and some function files that contain functions that are used in the main file. Such a file structure is shown as:
\dirtree{%
.1 my-project/.
.2 iterate.cpp/.
.2 iterate.h/.
.2 finalize.cpp/.
.2 execute.cpp/.
.2 initialize.cpp/.
.2 wait.cpp /.
}

This complex file structure requires linking of each header file, known as a library, to the main file which is labelled as \textbf{iterate.cpp}. This can be done using a program known as Makefile. Makefile is a library manager that links library paths together during the compilation step. Below is the Makefile for the above example:
\begin{verbatim}
    CC = clang++

    all: 
        $(CC) iterate.cpp initialize.cpp execute.cpp finalize.cpp wait.cpp -o one
\end{verbatim}
Let's walk through this. \textbf{CC} is a variable for the language. Here, we use the \textsc{clang++} compiler. Other options are \textsc{g++} or \textsc{gcc}. In Makefile, the variable is always a string and can be initiated by setting a name and a value. To call the variable, use the $\mathdollar$ symbol before the variable.

\begin{verbatim}
    CXX = g++
    CXXFLAGS := -Wall
    CXXFLAGS +=  -02

   main:
    $(CC) $(CXXFLAGS)iterate.cpp execute.cpp finalize.cpp initialize.cpp wait.cpp -o one

// called g++ -Wall -02 iterate.cpp execute.cpp finalize.cpp initialize.cpp wait.cpp -o one
\end{verbatim}

A CMake project consists of a file and a CMakeLists.txt file. The CMakeLists.txt file is a specific file, similar to a Makefile. Below is an example file structure, as well as an associated CMakeLists.txt file along with some comments.

\begin{verbatim}
    cmake_minimum_required(VERSION 3.20)

    project(some_project CXX)
    
    #json
    add_library(jsonLib INTERFACE)
    target_include_directories(jsonLib INTERFACE ${CMAKE_CURRENT_SOURCE_DIR}/json)

    #iscat file load
    add_library(iscat_file_load src/iscatloader.cpp)
    target_include_directories(iscat_file_load PUBLIC include)
    target_link_libraries(iscat_file_load PUBLIC HDF5::HDF5)

    #HDF5
    #add_subdirectory(include/h5pp)
    find_package(HDF5 REQUIRED COMPONENTS CXX)

    # add executable
    add_executable(main ${PROJECT_SOURCE_DIR}/app/main.cpp)
    # link libraries
    target_link_libraries(main PRIVATE jsonLib)
    target_link_libraries(main PRIVATE iscat_file_load)
\end{verbatim}
The explanations of each flags are listed in the list below;
\begin{itemize}
    \item cmake\_minimum\_required - Minimum required version of cmake
    \item project - defined project variable and version of C++
    \item add\_library - adds library. See explanation
    \item target\_include\_directories - tells the compiler where \textbf{.h} and \textbf{.hpp} files are located.
    \item target\_link\_library - The compiler will provide the target with the library. For instance passing in \textbf{(main\_program PRIVATE jsonLib)} will provide main with the functions and definitions in the library \textbf{jsonLib}. The flag ensures that nothing derived from the target main\_program will inherit functions in jsonLib. 
    \item find\_package - searches for external libraries. 
\end{itemize}

\subsection{HDF5 Files and their API}

The hierarchical data format, HDF, is a set of file formats that is used to store and organize large amounts of data. These are developed for supercomputer purposes, as well as general large datasets, such as those used in machine learning in recent years.

The HDF5 format consists of a large multi-dimensional array of identically typed elements. The datatype is defined across the dataset. The multi-dimensional array consists of a \textbf{Rank} and a set of \textbf{Dimensions}. The rank is a simple extensions from matrix algebra as the rank of a matrix.

The main trouble in HDF5 files is their nested-ness, specifically in the case of datasets where there are long nested strcutures. \begin{algorithm}[H]
\caption{Dynamic Programming for Best 2D Chain of Points}
\label{alg:best_chain_2d}
\begin{algorithmic}[1]
\Require 
    $\text{min\_idx} = \{ \text{min\_idx}[t] \}_{t=0}^{F-1}$, list of candidate positions per frame\\
    $\text{min\_vals} = \{ \text{min\_vals}[t] \}_{t=0}^{F-1}$, list of candidate values per frame\\
    $w = (w_x, w_y)$, weighting for distance computation (default $(1,1)$)\\
    $\text{max\_step}$, optional maximum allowed step distance
\Ensure
    $\text{idx\_chain}, \text{x\_chain}, \text{y\_chain}$, the indices, positions, and values of the optimal path

\State Initialize $F \gets |\text{min\_idx}|$
\State Initialize $cost[i] \gets 0$ for all $i$ in frame $0$
\State Initialize $prev \gets []$ \Comment{to store predecessor indices}

\For{$t = 1$ to $F-1$}
    \State $A_x \gets \text{min\_idx}[t-1]$, $B_x \gets \text{min\_idx}[t]$
    \State $A_y \gets \text{min\_vals}[t-1]$, $B_y \gets \text{min\_vals}[t]$
    \State Compute pairwise differences:
        \[
        \Delta_x[i,j] = |A_x[i] - B_x[j]|, \quad 
        \Delta_y[i,j] = |A_y[i] - B_y[j]|
        \]
    \State Compute weighted Euclidean distances:
        \[
        D[i,j] = \sqrt{ (w_x \Delta_x[i,j])^2 + (w_y \Delta_y[i,j])^2 }
        \]
    \If{max\_step is not None}
        \State Set $D[i,j] \gets \infty$ if $D[i,j] > \text{max\_step}$
        \If{no finite $D[i,j]$ exists}
            \State \Return empty path
        \EndIf
    \EndIf

    \State Compute cumulative path cost matrix:
        \[
        M[i,j] = cost[i] + D[i,j]
        \]
    \State For each node $j$ in frame $t$, find predecessor $p[j]$ minimizing $M[:,j]$:
        \[
        p[j] = \arg\min_i M[i,j], \quad
        new\_cost[j] = M[p[j], j]
        \]
    \State Update $cost \gets new\_cost$
    \State Append $p$ to $prev$
\EndFor

\State Initialize $j \gets \arg\min_i cost[i]$  \Comment{index of minimal total cost in last frame}
\State Initialize $\text{idx\_chain} \gets [0]^{F}$, set $\text{idx\_chain}[F-1] \gets j$
\For{$t = F-2$ down to $0$}
    \State $\text{idx\_chain}[t] \gets prev[t][\text{idx\_chain}[t+1]]$
\EndFor

\State Compute chains:
\[
\text{x\_chain}[t] = \text{min\_idx}[t][\text{idx\_chain}[t]], \quad
\text{y\_chain}[t] = \text{min\_vals}[t][\text{idx\_chain}[t]]
\]

\State \Return $\text{idx\_chain}, \text{x\_chain}, \text{y\_chain}$
\end{algorithmic}
\end{algorithm}
